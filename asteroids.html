Asteroids Clone (C)

  1. Portfolio
  2. Asteroids

Project Information

  • Role: Solo Developer
  • Language: C
  • Genre: Arcade / Physics Shooter
  • Tools: Visual Studio, ESAT Framework

Memory Management & Vector Physics

This project represents a significant technical leap in my early C programming journey. Moving beyond static arrays, I engineered this Asteroids clone to utilize dynamic memory allocation and vector mathematics, resulting in a robust, physics-driven arcade experience complete with a functional user account system.

Technical Implementation

  • Linked List Architecture: Managed the dynamic lifecycle of the asteroid swarm using custom singly linked lists. When large asteroids are destroyed, the logic securely frees the parent node and allocates two new medium nodes into the list structure.
  • Vector Math & Physics: Programmed progressive thrust, friction, and rotation by calculating vector magnitudes and normalizing 2D directional vectors for both the player ship and the procedural asteroid trajectories.
  • Circular Collision Detection: Implemented mathematical radius-based collision detection algorithms to accurately determine intersections between projectiles, the player, and irregularly shaped asteroids.
  • Data Persistence: Engineered a complete User Management state machine featuring Sign-Up and Log-In menus, safely serializing and deserializing struct data into local .dat files to track high scores and player profiles across sessions.

The Challenge & Learning

While managing dynamic memory for the linked lists was complex, the most demanding and tedious hurdle proved to be architecting the custom User Management system. Handling data persistence through raw .dat files meant engineering a reliable pipeline to serialize and deserialize player profiles, passwords, and high scores without data corruption. Navigating these low-level file I/O operations alongside the real-time game loop tested my patience, but ultimately solidified my understanding of data structures and scalable architecture in non-engine environments.
